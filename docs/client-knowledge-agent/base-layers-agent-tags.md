- Overview: We propose 39 tags and 66 topic areas for the agent's upload process, ready for you to sign off. Pillar 1 comes from Luke's Session Capture Form. The other nine pillars are drafts from the platform's pillar definitions until their forms exist.

- Decisions needed:
  - How does a new form update an older one? On the 27 October call we agreed that a re-upload under the same name replaces the document. The form says each upload adds to the client's record, and that a row stays blank if it was not discussed. Replacing the whole document would wipe every blank row's earlier advice. Recommendation: keep every form as a dated record. For each client, pillar and topic area, the latest agreed row is the current position. Blank rows change nothing, and older rows are returned only when someone asks for the history.
  - What can the agent say about where an answer came from? On the 27 October call we agreed clients do not need the source material, but the Statement of Work says the source document is named. Clients will also ask things like "what was the value proposition conversation I had with Luke?" Recommendation: name the session and date in the answer, but give no link or download of the form.
  - Do clients see recommendations that were not agreed? The form has an "Agreed?" column, and a client could read an unagreed idea as a commitment. Recommendation: show only agreed items as the current position. Show the others only if asked, labelled as not agreed. Make the column a fixed choice: Yes, No or Pending.

- Tags set at upload or by the system:
  - Client: chosen from the client list. If the name typed on the form differs, the upload stops.
  - Document type: session form, pillar document, review or delivery framework.
  - Uploaded by: the signed-in admin, shown in the upload log.
  - Upload date: the time of upload, shown in the upload log.
  - Status: Current, Superseded or Archived. Archived when a client leaves, and restorable if they return.

- Tags read from the form:
  - Pillar: the Pillar field, 1 to 10 or Review. Applied per section when a document covers several pillars.
  - Session date: the Date field. Decides which position is latest.
  - Session name: the Session field, such as "Positioning, Differentiation & Category Framing".
  - Attendees: names and job titles from the Attendees field.
  - BeDeveloped lead: any attendee who is BeDeveloped staff, so "the call with Luke" can be answered.
  - Captured by: the Captured by field.
  - Session summary: section 1.
  - Discussion topic: the Topic column in section 2.
  - Key point: the Key points column in section 2.
  - Client view: an opinion or position the client stated in section 2.
  - Challenge raised: an objection, risk or concern raised in section 2.
  - Topic area: the Area row in section 3, matched to the topic list below. Other rows are matched by AI.
  - Recommendation: the recommendation column in section 3.
  - Agreed status: the Agreed? column in section 3.
  - Action: the Action column in section 4.
  - Action owner: the Owner column in section 4.
  - Action due date: the Due date column in section 4.
  - Next session date: the Date row in section 5.
  - Next session focus: the Focus row in section 5.
  - Preparation needed: the Preparation needed row in section 5.

- Tags the AI finds in the text:
  - Job titles and buyer roles: any role named as a target or decision maker, such as the job titles agreed for an ICP.
  - Target organisations: organisations, sectors or segments named as targets for outreach.
  - Competitors: competitors or alternatives named.
  - Position change: wording that shows a new position replacing an old one, such as an updated value proposition.
  - Proof points: figures, outcomes, case studies or references.
  - Associated terms: matches against George's term library, added to help search.

- General overview tags the AI writes:
  - Main points: the three to five most important points across the whole document.
  - Key takeaways: what the client should remember or do differently as a result.
  - Common themes: ideas that recur across different topics in the document.
  - Key decisions: every decision made, wherever it appears in the document.
  - Pillar key points: the main points for that pillar, such as "Value Proposition key points".
  - Topic area key points: the main points for one topic area, such as "ICP key points".
  - Open questions: anything left unresolved or still to be decided.
  - Client context: background on the client's business, market or situation that frames the advice.
